Mica — a calm app that has no motion yet

A full audit of Mica's motion design — or rather, near-total absence of it. Seven conditional renders snap. One infinite loop has no accessibility guard. The brand promises calm; the interactions promise nothing at all.

Overall

Mica's design language is considered and warm — bloom circles, muted accents, careful typography. But the motion layer is essentially empty. Every state change in the app snaps: loading to content, empty state to event card, tab to tab, date picker in and out. The one animation that exists — a splash spinner — is a looping continuous animation with no reduced-motion guard, making it the app's only accessibility gap. The clean slate is a gift: there is nothing to undo, only to add purposefully.

Issues to address
Critical Jakub

Loading state snaps directly into the home screen

WhatWhen events finish loading, HomeScreen replaces the full-screen ActivityIndicator with the scroll view and all its cards in a single frame — no enter animation, no crossfade, no sense of the content arriving.

Why it mattersThis is the first thing users see every time they open the app. A snap here feels like a flash of content, not a calm reveal. Jakub's core technique — opacity + translateY + blur — exists specifically for moments like this: making content feel like it materialises rather than pops.

Recommended motion

Wrap the loaded content in an Animated.Value that drives opacity (0→1), translateY (10→0), and an interpolated blur via a native shadow workaround, triggered once on mount. Use useNativeDriver: true and 280ms with Easing.out(Easing.cubic). Pair with AccessibilityInfo.isReduceMotionEnabled() to skip animation when reduced motion is on.

Critical Jakub

Next Up card and empty state swap with no transition

WhatThe ternary at HomeScreen.tsx:102 renders either the "Next Up" spotlight card or the empty state dashed card. When the user adds or deletes their last event, the two views snap-swap — the old card vanishes and the new one appears in a single frame.

Why it mattersThis moment is emotionally meaningful — adding your first event, or seeing an empty horizon. Abrupt visual teleportation undermines the calm brand. A Jakub-style enter (opacity + scale + blur) on whichever card mounts makes the arrival feel intentional and considered.

Recommended motion

Use a keyed Animated.Value per card state that triggers a mount animation: opacity 0→1, scale 0.96→1, over 240ms with Easing.out(Easing.cubic). Since this is React Native (no AnimatePresence), drive it from useEffect on mount. The exit can be instant — the entering card is what matters here.

"More coming up" section appears and disappears instantly

WhatThe rest.length > 0 && guard at line 182 mounts or unmounts the entire secondary events card with no animation. Users who add a second event see it blink in; users who delete their penultimate event see it blink out.

Why it mattersThis is a moment of genuine positive feedback — the user's calendar is growing. A subtle stagger-enter on the section would make adding that second event feel rewarding without demanding attention on repeated views.

Recommended motion

Animate the section mount: opacity 0→1 and translateY 10→0 over 220ms with a 60ms delay relative to the primary card. On unmount, instant removal is fine — Jakub's rule: exits can be subtler. Use useNativeDriver: true.

Important Jakub

Date picker appears without an enter transition

WhatThe showDatePicker && <DateTimePicker /> at line 262 causes the native picker to mount instantly inline. On iOS (inline display="default"), this means a large UI element pops into the scroll view without warning.

Why it mattersThe inline iOS date picker is 200px+ tall. An instant appearance of that much content is jarring — it pushes content below it down without spatial context. A slide-down + fade over 220ms gives it the spacial continuity of a real disclosure.

Recommended motion

Wrap the picker in a custom Animated.View container. Animate height from 0 to the picker's natural height (use LayoutAnimation.configureNext for the height, which handles layout, or use a fixed 210px with overflow: hidden). Fade in with opacity 0→1, 220ms. On iOS only — Android spinner dialog handles its own animation natively.

Important Jhey Jakub

Onboarding pagination dots change size and color instantly

WhatThe PitchScreen pagination dots at line 296 swap between active (8×8px, accentStrong) and inactive (6×6px, surfaceMuted) with a direct style swap — no interpolation, no transition. Each swipe through the three onboarding panes triggers this instant snap.

Why it mattersThis is the first interactive feedback the user gets in the app. Onboarding is where delight earns its keep — it's a one-time moment, not a high-frequency action. A 180ms transition on the active dot (scale + opacity) would make each pane feel like an arrival, not a frame swap.

Recommended motion

Use an Animated.Value per dot driven by the current page index. Interpolate scale from 0.75→1 and opacity from 0.35→1 over 180ms with Easing.out(Easing.cubic) as each dot becomes active. Since transform: scale works with useNativeDriver: true, this is zero layout cost.

Issues to address
Critical Emil Accessibility

The only animation in the app has no reduced-motion guard

WhatThe SplashScreen runs an Animated.loop(Animated.timing(spinValue, { duration: 1000 })) — an infinite spinner. There is no call to AccessibilityInfo.isReduceMotionEnabled() or AccessibilityInfo.addEventListener('reduceMotionChanged', ...) anywhere in the codebase. For the 17% of users with vestibular disorders, a continuously spinning element with no off-switch is an accessibility failure.

Why it mattersReduced-motion support is not optional. Emil's framework is built on purposeful, non-intrusive motion — the first principle of which is respecting user intent. A looping spinner that ignores the system accessibility setting violates that principle at the most basic level.

Recommended motion

Check AccessibilityInfo.isReduceMotionEnabled() before starting the spin loop. If reduced motion is on, skip the Animated.loop entirely and show the spinner as a static element (or substitute a simple opacity pulse at <1Hz, which is vestibular-safe). Subscribe to reduceMotionChanged to catch runtime changes. React Native 0.83 supports this API natively — no extra dependencies needed.

Important Emil Jakub

Tab bar active state has no transition at all

WhatThe TabBar at line 39 computes color and fontWeight directly from isActive — no animated value, no transition. Every tab press swaps icon, color, and weight in a single frame. This is the highest-frequency interaction in the app.

Why it mattersEmil's frequency gate says: frequent actions should have minimal or no animation. But "no animation" and "instant visual snap" are not the same thing. A 150ms crossfade on icon opacity gives the brain just enough signal to register the switch without creating animation debt across hundreds of daily presses. Jakub adds: ignoring hover/press transitions is the most common place polish breaks down.

Recommended motion

Use two Animated.Value instances per tab: one for the active icon opacity (0→1 when activating, 150ms), one for the label weight (this can't be interpolated in RN, so accept the font-weight snap and focus on the icon crossfade). Keep useNativeDriver: true for the opacity. Total animation budget: 150ms maximum — Emil's rule for frequent actions.

Emil's framework starts with the frequency gate — should this animate at all? For Mica's high-frequency tab bar, the answer is almost no; for the once-daily home screen load, yes. The one hard failure is the unguarded looping spinner: for Emil, accessibility isn't optional, and a spin animation that ignores the system setting is a regression to fix before anything else. The good news: there's nothing to remove, only to add carefully.

Jakub Krehel — Production Polish

Mica is a consumer mobile app used daily. The primary gap is not in animation philosophy but in the absence of basic production-quality enter/exit motion on primary UI states. Jakub's opacity + translateY + blur recipe and his principle that exits should be subtler than enters are the most directly applicable tools here.

  • More Jakub Add enter animations to every conditional render — the loading state, the Next Up card, the "More coming up" section. Use opacity + translateY with Easing.out(Easing.cubic) and useNativeDriver: true. Exit animations can be instant.
  • More Jhey Explore the year grid as an animated object. The 365-dot stagger on first render is a signature moment waiting to happen. Treat the countdown numbers as display elements worth a theatrical enter on screen focus.
  • More Emil If usage data shows tab switching exceeds 50+ taps/day per user, remove the tab transition entirely — keep the haptic, drop the visual. Emil's frequency gate is absolute for truly high-frequency actions.
